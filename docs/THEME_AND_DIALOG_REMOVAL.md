## Required behavior

- Remove `StepInspector.tsx` and every `StepInspector` import/render from Flow and Customize. The INSPECT STEP header, close button, partition/message dialog content, overlay positioning, and overlay focus/Escape behavior are retired together. Do not replace the component with another dialog, drawer, floating inspector, or hidden equivalent.
- Flow retains compact controls, readable aggregate partition cards, normal selection/focus, pan/zoom/minimap, and finite correctly routed packets. Selecting a node, edge, or retained record control must not open the retired overlay or set up a hidden focus trap. Do not delete simulator records/events to remove the UI.
- Customize retains its six sections, configuration controls, normal Activity partition/details panels, metrics/timeline, and the embedded `InspectorPanel`. Shared inspection state/actions may remain where those normal details require them; removing the step-dialog presentation must not erase the Activity data model. Delivery outcomes, failure/retry/manual commit, example actions, and Guide experiments remain intact.
- Add one native keyboard-accessible theme toggle at the far right of the shared header on every route. Its accessible name/action and text/icon identify switching between light and dark; focus remains visible, current choice is understandable without color alone, and the header remains usable at 320px/390px without page overflow.
- Fresh/missing/invalid preference defaults to **light**. Light uses warm white/black/gray/red; dark uses charcoal surfaces, readable light text, gray structure, and red accents throughout the app: shell/header/navigation/footer, canvas/nodes/links/controls/minimap, Customize panels/forms/charts, Guide/experiment tables, and Practice hub/questions/feedback.
- Theme is independent presentation state, persisted under `kafkalab:theme:v1` as validated JSON `{ "version": 1, "theme": "light" | "dark" }`, with only `light` and `dark` accepted. Apply a valid saved choice before first visible paint and keep React hydration consistent so reload does not flash the opposite theme. Unavailable/quota-blocked storage must leave the app usable with session theme switching.
- Switching theme does not reset, advance, pause, or otherwise mutate simulator records, offsets, delivery history, playback, charts, Practice answers, or `kafkalab:learning:v1` progress. All domain/progress resets preserve theme; clearing/changing theme preserves the other stores. No dependencies or backend are added.
